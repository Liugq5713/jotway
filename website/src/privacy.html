Where your
words go.

App access, optional AI, indexing and local records have different boundaries.

This guide includes development-preview behavior. Notes assistance and local application matching require an unreleased source build; do not assume the current download contains them.

01 · On your Mac

The working draft stays in process memory while you hide and reopen the panel. Quitting clears that working copy, but enabled Local Records can also save unsent drafts and activity to disk. Closing a panel does not delete those records or historical debug archives.

Preferences, app usage and operation records are stored locally. API keys use account-restricted local credential files, not the system Keychain. Jotway has no browsable inbox or resumable conversation history.

macOS permissions and selected Notes folders bound access. Apple apps may sync received content according to their own account settings.

02 · Review before saving

Confirming Notes writes to your selected folder. Jotway cannot retract content already received by another app.

Optional Notes assistance can add separate insights or related history. Notes retains the complete original even when optional assistance fails. Local application matching never sends typing-time drafts to an intent service.

03 · Optional network processing

Providers may charge for requests and apply their own retention policies. Deleting local data does not retract data already sent.

Notes indexing and related history

When enabled and configured, text from the chosen Notes scope is read and indexed locally. Indexing and queries can send text to the configured embedding service. The local index contains readable note content as well as vectors. Search covers the indexed scope and refresh state, not necessarily the entire or live library.

Notes AI assistance

Fast models generate titles and group Notes; deep models prepare optional supplements. Each capability has a primary and optional fallback model. On eligible service failures, the same text and context may be sent once to the fallback, and each service bills its own account. Accepted work keeps its frozen configuration. Cancellation and finite deadlines prevent late adoption; a model retry never repeats the Notes write. Connection tests call only the chosen model using sample content.

04 · Local records and clearing

Local Records
Text revisions, including unsent drafts, and routing or execution events may be saved. Settings → App Suggestions controls capture, retention (90 days by default), export and clearing. Turning capture off requires confirmation and deletes existing operation records.
Personal Agent archives
Historical question and model content from earlier versions remains untouched until manually deleted. Personal Agent is retired; current Notes model calls do not create these files. Technical-log clearing does not erase old archives.
Notes index
Indexed note text and vectors remain in the local index. Use the Notes history controls to manage its scope and index. Removing a service key does not itself erase already indexed text.
App usage
App identities, open counts and recent open times are stored separately. Clearing operation records does not clear app usage or data in Apple apps.

05 · Technical logs are separate

Runtime logs contain bounded stages, identifiers, outcomes and timings, not draft bodies or keys. They keep today and the previous six days, with 10 MB per file and 50 MB total. Settings → General → Runtime Logs offers open, export and clear controls.

Those controls do not clear Personal Agent full-content archives, operation records, preferences or provider-side data. Chrome Source is separately opt-in: it may read the front Chrome tab near a recent copy, with plain-text fallback when unavailable. It is independent of Clipboard history.
