# Proposal

## Why

当前 Instant Insight 把回答限制为翻译、解释或洞察之一，并按类型严格限制字符数、段落数和问号数量，用户也无法自行调整提示词。需要在现有单次请求流程内放宽回答形式，让手动 ⌘J 与自动提示共用一套可编辑提示词和回答规则，避免同一草稿因触发入口不同而受到不同的内容限制。

## What Changes

- 手动与自动请求统一使用 answer／none，按当前草稿和同一份有效提示词组织内容，可组合翻译、解释、总结、比较及文字层面的步骤建议；详略由请求和提示词决定，不预设简短或要求用户先选模式。
- 两种入口使用相同的 4,000 字符总上限和基础 Markdown 展示，支持段落、标题、列表、强调、代码与简单表格，取消按来源或语义类型划分的短字符／段落限制。
- 写作偏好提供一份 Instant Insight 提示词的编辑、保存、取消及恢复默认，保存后对手动和自动请求共同生效；用户可以修改帮助方式和表达偏好，程序独立维护输出协议、总上限与内容／执行边界。
- 自动提示通过默认关闭、停写评估、重复请求抑制、不抢焦点，以及加载／无回应／失败静默来保持克制；内容选择、澄清规则和回答格式与手动请求一致。
- 继续使用现有模型配置、一次模型调用及临时只读结果面板；保持输入法保护、取消、过期结果隔离及草稿／存入边界，不接入搜索服务、工具调用、多轮对话、聊天历史或自动写入能力。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `draft-thinking-prompts`：统一两种触发入口的回答语义、输出校验、呈现和提示词偏好，增加共用配置的快照规则，保留既有触发、反馈与隐私边界。

## Impact

- `DraftThinkingPromptGenerator` 的统一生成规则、响应类型与校验；`DraftThinkingPromptSession` 的共用提示词快照及按来源处理的调度和反馈。
- `SettingsView`／`InstructionEditor` 的共用提示词入口，以及 `AppState`、`LauncherSession` 中的本地偏好装配和变更通知。
- `DraftThinkingPromptView` 的只读回答展示和相关本地化文案。
- 实施时同步 `CONTEXT.md` 中的 Instant Insight 定义及 AI、产品概览、写作偏好的 Current 文档，不改动 action 路由。
- 新增独立的本地提示词偏好，不迁移数据库或旧 AI 背景配置；不新增外部 API、服务配置、第三方依赖或回答历史，没有已保存回答需要迁移。
