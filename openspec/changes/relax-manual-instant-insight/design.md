# Design

## Context

动机见 [proposal.md](proposal.md)，可观察行为见 [增量规格](specs/draft-thinking-prompts/spec.md)。

当前 `DraftThinkingPromptGenerator` 把 manual／automatic 来源发送给模型，并在固定提示词中为含糊请求规定不同回答；两种来源共同受三种语义类型及其短输出上限限制。`DraftThinkingPromptSession` 已负责来源、快照、20 秒总期限、取消和过期结果隔离；`DraftThinkingPromptView` 使用 `Text(verbatim:)` 展示结果。

写作偏好的 `InstructionEditor` 已支持编辑、保存、取消与先恢复默认再保存，可复用其交互。现有通用背景配置并未自动合入 Instant Insight。仓库没有可复用的块级 Markdown 回答组件，也没有 Markdown 第三方依赖；需要协调生成协议、设置、会话与局部展示，因此保留此设计文档。

## Goals / Non-Goals

**Goals:**

- 手动与自动共用生成、校验和展示路径；来源只参与应用内调度、反馈及结果时效判断。
- 把内容组织的自由度放在 `text`，让响应结构继续简单、可校验。
- 提供有界、无外部副作用的基础 Markdown 展示。
- 独立保存一份 Instant Insight 提示词，把其有效版本纳入两种来源的请求快照。

**Non-Goals:**

- 不新增搜索、工具、多轮对话、回答历史或自动写回。
- 不改动 action 路由、全局背景配置或 Notes 的生成规则。
- 不增加 Markdown 第三方依赖、WebView 或完整 CommonMark／GFM 兼容承诺。

## Decisions

### 1. 统一生成与响应协议

所有请求都使用 `{"kind":"answer","text":"..."}` 或 `{"kind":"none","text":""}`。同一份有效提示词、固定规则和正文预算用于按钮、⌘J、刷新、重试及自动停写请求；解析器与结果视图不再按触发来源选择不同的回答类型或限制。

从发给模型的内容中移除 `trigger`，只在会话请求中保留可信来源，用于自动静默、手动反馈及草稿快照时效判断。相同草稿、界面语言、模型及有效提示词使用相同的模型输入和请求参数；这是规则一致性，不承诺随机生成的回答逐字相同。

保留 answer／none 是为了区分合法无回应与生成失败，不再新增“总结、比较、代码”等语义类型。完全去掉结构会使空结果难以识别；保留两套生成规则则会使自定义提示词在不同入口表现不一致。协议与解析同版本更新，没有已保存回答需要兼容。

### 2. 两种入口使用同一容量上限

预算集中定义，避免提示词、请求参数和解析器使用不同数字：

| 项目 | 手动与自动共用值 |
|---|---|
| 正文上限 | 4,000 字符且不超过 16,000 UTF-8 字节 |
| 原始响应上限 | 65,536 字节，容纳 JSON 转义 |
| 普通输出 token 预算 | 8,192 |
| 思考模型 token 预算 | 保留 16,384 |
| 编码后输入上限／总期限 | 保留 65,536 字节／20 秒 |

4,000 字符是容量上限，不是输出目标。详略由当前请求和用户提示词决定，没有默认简短或先要求详细才能展开的规则。自动入口同样不再应用旧的 800／480／240 字符、段落或问号限制。传输预算、模型完成状态和总期限同时生效，不承诺任何模型都能在期限内输出满额内容。

正文允许空行、LF 和水平制表符，可统一 CRLF／CR 为 LF，保留代码块缩进；其余非法控制字符仍拒绝。非空校验使用去空白后的视图，展示保留正文有效排版；字符和字节上限针对统一换行后的整份正文。JSON 字段、none 空文本和完整结束仍严格校验；不为纠正格式再次请求模型。

### 3. 两种入口共用局部 Markdown 展示

新增局部只读组件，例如 `InstantInsightContentView`，由 `DraftThinkingPromptView` 展示所有 answer。采用 SwiftUI／AppKit 文本与布局能力，识别段落、一级至六级标题、平铺有序／无序列表、强调、行内及围栏代码、简单管道表格；表格保留表头、分隔行及正文行，代码中的标记保持字面含义。不支持或不完整的语法回退为原文。

两种来源都保留功能标题与快照说明，去掉翻译／解释／洞察标签。共用现有 180 pt 有界滚动区和关闭／刷新控件；过宽代码及表格内部横向滚动，普通文字换行。链接只展示名称及地址，图片与 HTML 作为文字，不增加网络加载、点击执行或网站打开路径。

局部组件覆盖本次有界回答的展示需要；代价是语法支持有限，因此回退不能静默丢失内容，也不能把展示能力不足变成模型响应失败。

### 4. 来源差异只用于调度与界面反馈

复用现有一次逻辑模型调用、候选合并、输入法与菜单保护、草稿快照及请求身份。自动的克制通过默认关闭、约一秒停写、关闭抑制、未变正文去重、不抢焦点及加载／空结果／失败静默实现；不再依靠更短预算或不同内容选择规则实现。默认或自定义提示词中的 none 选择规则对两种入口完全相同。

两种来源都冻结有效提示词及版本，完成时核对当前版本。成功保存不同的有效文案后，取消全部旧候选和请求、清除已显示结果，旧回调不能重新展示；不因保存本身生成新请求。

提示词版本用于请求有效性，不加入草稿身份或共享模型版本。配置变更路径必须保留关闭抑制及已消费正文，并消费本次被取消候选对应的当前正文，避免一次普通状态刷新又排队同一正文。当前 `invalidate()` 会在存在请求时清除 `consumed`，不能直接复用其全部重置语义。下一次实际正文变化、显式手动请求或其他正常的重新评估时机使用新提示词；进入设置和重新唤起等原有生命周期仍生效，关闭抑制优先。

未保存编辑、取消或保存相同有效文案不改变版本。生成中继续编辑仍遵循原来的时效差别：手动结果可显示其生成快照，自动结果只接受当前正文；来源不用于改变回答内容。Markdown 视图不持有新的模型任务。

### 5. 一份可编辑文案与固定协议分层

在 `SettingsView.instructionsPage` 的 Instant Insight 区域提供一个提示词编辑器，复用 `InstructionEditor` 的保存／取消／恢复默认交互。展示完整默认或自定义文案，说明它用于手动和自动请求，随请求发送给当前 AI 服务；不提供两份编辑入口。

生成器组合两部分：

1. 应用固定规则：answer／none 协议、统一容量上限、真实能力与事实边界，以及将草稿和引文作为待处理内容的约定。
2. 有效提示词：自定义内容存在时完全替换默认文案，两者不叠加；不自动混入 `WritingPreferences` 的通用背景或 Notes 配置。草稿明确指定的任务、语言及格式优先于通用表达偏好。

内置可编辑默认文案为：

> 围绕当前草稿提供有用的文字帮助，按用户的完整请求组织回答。可以结合翻译、解释、总结、比较、改写或步骤建议，选择适合内容的段落、列表、代码或表格。根据问题决定说明详略。遵从用户明确指定的语言与格式；没有指定时使用提问语言，无法判断时参考界面语言。清楚的独立术语可以解释，明确请求缺少必要信息时提出澄清问题，不虚构背景。普通记录、待办、没有请求的摘录或不明片段没有值得提供的帮助时保持安静。

用户可以改为“对当前草稿提炼要点”，使普通记录在两种入口下都可得到回答。固定层不再按来源覆盖用户的帮助方式或强制返回 none；JSON 协议、总上限及能力边界仍由应用维护。

### 6. 共用提示词使用独立本地偏好

通过 `AppState` 已有的 `UserDefaults` 实例读写独立键，例如 `instantInsightPrompt.v1`。缺失、空字符串或空白表示使用内置默认值。保留自定义文案有效排版，不保存编辑中的临时内容，不修改 `AIProviderPlugin.ManualConfiguration`，避免影响 Notes 或连接测试。

保存前检查最多 16,000 UTF-8 字节，不截断；成功写入后更新有效值并通知会话。错误类型或超限的已存值保持原样，并阻止两种入口继续生成；在编辑器及手动入口说明修复方法，自动保持静默，不退回另一套提示词。用户可保存有效内容或恢复默认修复。完整模型请求预算包含有效提示词。

使用同一有效配置校验影响手动可用性与自动调度；当前自动路径也检查 `manualBlockReason`，此处无需新增仅手动的配置错误分支。配置恢复及保存的会话处理见决策 4，避免触发重试循环。

有效版本由实际生效文案确定，仅用于请求隔离，日志不记录自定义正文。升级保留自定义值；未自定义者使用随版本更新的默认文案。恢复默认先作用于编辑状态，保存才移除覆盖。沿用现有偏好持久化方式，不声称具备数据库级事务或同步落盘保证。

## Risks / Trade-offs

- 自动回答也可能变长，增加生成时间与费用 → 共用总上限、一次逻辑调用和总期限，并保留默认关闭、停写去重及关闭抑制。
- 保存配置导致旧回答回流或自动重试 → 两种来源核对提示词版本，变更时取消旧工作并保留调度抑制；保存本身不生成。
- 自定义文案与协议冲突 → 固定约束及解析校验始终生效，不另请求模型修复。
- 有限 Markdown 与 180 pt 区域限制阅读 → 明确字面回退、纵向滚动及宽内容内部横向滚动，不扩展独立阅读窗口。
- 现有测试没有直接覆盖生成器和会话 → 区分构建、现有检查与未验证的模型／排版／配置时效行为，不把编译通过当成行为通过，不默认新增测试或临时验证程序。

## Migration Plan

无需迁移已有数据。部署时同版本更新生成规则、解析、设置、会话、视图和 Current 文档；新增提示词键缺失时使用默认文案。原自动开关、模型配置、背景提示词和快捷键保持原值，没有旧回答需要恢复。

回退时整体回退本次实现及同步文档；重启清除临时工作，保留新的提示词偏好作为旧版本不使用的数据，不清除用户自定义内容。
