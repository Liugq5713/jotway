# Design

## Context

动机见 proposal.md。个人配置已有版本化偏好与独立凭据，生成入口由 ModelConfiguration 统一执行托管优先。原服务卡片受展示开关控制，必须保持可恢复。

## Goals / Non-Goals

通过已有两类协议覆盖常见服务商，以显式、独立的目录请求降低填写成本。保持单个人配置结构、托管优先和原生成传输；不增加模型注册平台、SDK 或多账号。

## Decisions

1. 预设按协议及规范化官方地址识别，不新增持久化字段。自定义保留可编辑地址，切换预设清空未保存 key 与模型，防止错配。相比存储品牌字段，此方式不需要迁移，也不会让修改后的地址冒充官方预设。
2. 抽取不依赖模型 ID 的地址校验，以及保存／目录共用的凭据解析。没有新输入时，只有已存配置的相同地址与协议能复用 key。目录操作冻结地址、协议、key，禁止重定向；不复用托管凭据。
3. 新增轻量目录传输：GET Base URL/models，OpenAI 兼容协议用 Bearer，Claude 用 x-api-key 与版本头、limit=1000。使用临时 URLSession、20 秒资源期限、2 MB 响应上限、最多 1000 个展示项；仅取首批，明确标记分页或截断，不跟随服务返回的 URL。解析、去重合法 ID；列表不保证文本能力，生成测试另行验证。
4. 目录状态与生成测试状态独立。页面编辑取消运行中的请求，地址／协议／key 变化清理目录；模型编辑保留可选列表。请求标识和配置版本防止旧结果覆盖。保存与打开不发请求。原始网络错误映射为固定文案。
5. 生成测试继续调用当前生效的 deep 入口和固定样例；按钮、提示和结果标示实际目标。有激活码时明确个人配置尚未生效及使用 Jotway 额度，不静默绕过托管优先。

## Risks / Trade-offs

- 列表可能含非文本模型或不支持当前生成协议的型号 → 保留手填并说明目录不等于生成验证；失败不自动切换模型。
- 自定义服务可能没有模型目录或仅返回部分数据 → 显示具体类别的固定错误／不完整提示，手填始终可用。
- 没有真实服务凭据验证 → 使用构建、现有相关测试和代码检查；明确实网模型质量未验收，不新增测试或使用用户凭据。

## Migration Plan

无需迁移配置。实现后同步主规格与当前说明，执行必要检查、提交并更新安装。回退代码即可恢复旧表单，已有偏好和 key 格式不变。
