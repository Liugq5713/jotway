# Design

## Context

动机见 [proposal.md](proposal.md)，行为以 [增量规格](specs/notes-review/spec.md) 为准。

`AppState` 已持有 `NotesReview`，因此隐藏面板不再结束生成；但是 `NotesReview` 只有一个 `period`、请求及流式发布状态，`load` 会先取消此前任务。`LauncherSession.syncReview` 也依据这个单一周期映射结果。直接在定时器里调用现有 `load(.today)` 会抢走周回顾，必须先分离请求状态与展示选择。

`NotesReviewLibrary` 已集中处理现有授权、范围版本、最多 60 篇及每篇 4,000 字符限制。已有完成缓存仅在内存保存 6 小时。设置由 `AppleNotesModule` 写入偏好并通知刷新；`JotwayAppDelegate.startDeferredWork` 提供应用启动后的非窗口工作入口。

## Goals / Non-Goals

**Goals:**

- 使调度只决定“是否受理一次今天回顾”，继续由原回顾模块负责来源、模型、流式结果及失效。
- 用同一套生成路径服务手动和自动运行，按周期隔离并发状态，保留手动导航的既有取消语义。

**Non-Goals:**

- 不建立通用任务队列、独立进程、系统唤醒任务或跨进程生成恢复。
- 不扩展现有回顾缓存寿命，不持久化摘要或来源正文。

## Decisions

### 1. 应用持有一个专用调度器，窗口不拥有调度

增加 `NotesReviewScheduler`，由 `AppState` 持有，在 `startDeferredWork` 中幂等启动。它持有取消句柄和调度版本，调用 `NotesReview` 的自动请求入口，不访问 `LauncherSession` 或窗口。

选择应用内单次定时等待，每次重新计算下一个本地日期的指定时分，而不是每隔 24 小时执行。启动、设置变化、日期／时钟／时区变化以及睡眠／唤醒统一撤销旧等待；回调必须验证调度版本、日期和当前时间。复用仓库现有系统通知接入方式，释放时注销观察与等待。

不用窗口定时器，因为关闭窗口必须仍能生成；不用系统调度服务，因为用户已选择错过即跳过，不需要退出后启动能力。

### 2. 只消费预先安排的机会，不从“现在已过时间”推导立即执行

保存 `notesReview.automaticEnabled` 和 `notesReview.automaticMinuteOfDay`，时间值为 0–1439；未配置或无效时使用 21:00。新增偏好默认关闭，属于实现假设；用户可自行设置，不迁移或覆盖 `notesReview.enabled`。

计算使用跟随系统时区的公历日期与当地时分，不使用固定秒数推导明天。启动或重算只能安排严格晚于当前时刻的目标，且不存在的时分跳过、重复时分取首次。单次等待醒来后，只接受目标分钟内且没有睡眠或时钟变更的回调；超过该分钟跳过。睡眠撤销等待，唤醒只计算未来目标，即使在目标分钟内唤醒也不能恢复已过的回调。

在读取 Notes 前先消费当日机会，保存不含正文的最新已处理本地日期 `notesReview.automaticLastHandledDay`，用公历年月日比较。到时条件不可用也消费机会；正常重启、重复回调或改时不重置标记。识别到当天已错过的已启用计划时同样记录该日为已处理，避免修改时间后意外补跑。时钟回拨到该日或更早日期时暂停自动机会，直到日期超过标记。手动请求不读写这个标记。

不把失败重试与权限恢复接到调度入口；模型内部既有请求策略保持不变，但一次终态失败后不再创建新的自动任务。关闭自动开关只停止未来机会，已受理任务继续；关闭回顾总开关仍触发既有失效。

### 3. 在现有回顾模块内按周期保存请求，不复制业务服务

将 `NotesReview` 中的请求 ID、冻结身份、任务、预览发布任务和状态收敛为按 `NotesReviewPeriod` 保存的内部请求状态；保留共用配置观察、来源库、解析逻辑和完成缓存。最多一个今天请求和一个周请求。

展示周期仍由用户导航选择。自动入口只更新今天状态，不设置展示周期；`LauncherSession` 按 `state.reviewPeriod` 获取对应快照，只有该周期更新影响已打开详情。

每个请求记录是否已被当日调度持有。自动入口发现同日同身份今天任务时，为其增加自动持有而不新建；否则绕过较早完成缓存启动今天请求。手动打开共享有效任务或缓存；保留服务已有 `force` 路径，仅替换对应周期旧任务。当前界面没有独立刷新按钮，本次不新增该入口，失败后的手动重试继续通过关闭再打开完成。切换周期仍取消仅手动持有的旧请求，自动持有的今天请求继续。

校验改为检查对应周期请求 ID 和冻结身份，不再依赖当前展示周期。配置、范围或权限失效取消全部相关周期；发布回调和完成写缓存均验证各自 ID，避免迟到结果。跨日今天请求按既有窗口校验失效。

不另建第二个 `NotesReview` 实例，因为独立实例会使今天的手动与自动缓存分裂，并重复来源读取。也不将定时任务排在周回顾后等待，因为等待可能把运行变成错过后的补跑。

### 4. 在原设置区添加时间选择并明确读取触发条件

偏好访问继续通过 `AppleNotesModule`，在 `AppleNotesSettingsView` 的现有回顾区使用原生时间控件。总开关关闭时禁用自动控件，但保留值。修改调度时间只更新调度版本，不改变回顾身份和来源范围。

同步更新 `notes.review.enable.help`、`notes.review.privacy` 及新增中英文文案，说明只有手动请求或已启用的每日时间才会发送有限原文；注明错过即跳过和运行条件。

## Risks / Trade-offs

- 日期回拨后可能需要等待日期超过最新已处理日 → 设置仍可手动运行；这一选择优先避免同一日期重复自动发送。
- 周回顾与自动今天回顾可能同时调用模型 → 并发上限为每周期一个，不创建积压队列；同一天今天请求共享。
- 主线程长时间阻塞可能使预定分钟错过 → 按跳过策略处理，不将延迟回调变成补跑。
- 自动结果在退出或缓存过期后不可直接查看 → 保留现有内存边界和手动生成入口，不引入未经请求的正文存储。
- 已有 `docs/integrations/apple-notes.md` 仍提到周／月缓存及关闭取消，与当前代码和主规格不符 → 实现时一起修正同一回顾段落，描述今天／周回顾和隐藏后继续的现状。

## Migration Plan

仅新增调度偏好及日期标记，无数据库迁移。升级后自动回顾默认关闭；回退版本忽略新偏好，仍保留原手动回顾。停用自动开关即可停止未来调度，不清理来源数据或更改 Notes 授权。
