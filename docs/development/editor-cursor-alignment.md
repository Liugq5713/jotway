# 编辑区空行光标几何后续

> Role: **Work**
> Status: 未交付；公开原生映射方案仍需确认。高度回缩已按用户决定独立交付，不能据此关闭本项。
> 需求编号：`docs/product/editor-refinement.md#cursor-alignment`（沿用既有调度项）

## 问题与边界

当前正文使用 16 pt 系统字体，以原生字体行框加额外行距实现普通中英文 26 pt 基线间距。连续空行和末尾空行的原生插入点仍可能把行距算入矩形。用户已选择先交付高度回缩，空行光标另列后续；本 Work 保留该未完成契约，不把高度修复或构建成功视为光标验收。

已交付的自动高度行为见 [Product overview](../product/overview.md)：快捷输入保留 122 pt 卡片下限、52 pt 编辑区偏好、360 pt 自动卡片上限及无下方内容时的 290 pt 编辑区上限；正文删除后可按当前布局回缩，手动高度和便签仍遵循各自策略。本后续不再重做高度链，也不恢复旧的 96 pt 下限。

## 待确认方案

目标仍是让空行插入点使用实际字体度量，同时保留 26 pt 普通基线间距。不得硬编码光标高度、自绘或单独移动光标，也不切换排版引擎。正文、typing attributes、占位文字、选区及输入法候选窗必须使用一致的原生布局。

公开 `NSTextLayoutFragment`／`NSTextLineFragment` 包装探索尚未形成可交付方案：增量布局曾出现额外行片段重复；显式失效布局虽能消除重复，却在真实 `NSTextView.firstRect(forCharacterRange:actualRange:)` 的末尾空行查询中返回零矩形。同一真实窗口、选区及调用，撤去适配后原实现返回 26 pt 高矩形。失败适配已撤除，不能仅凭片段数组或自定义矩形正确就认定原生映射正常。

下一阶段先确认公开 API 能否保留原生字符位置到行片段的映射，以及实际光标、选区和输入法定位是否一致。若无法满足约定，应带证据提出新设计决定；不得继续猜测或把计划标记为实施就绪。

## 验收条件

1. 使用真实 `EditorView` 和 `NSTextView`，覆盖空态、首字、行首／行尾、连续空行、末尾空行及自动折行。普通中英文基线保持 26 pt，光标与所在行字体排版框中心差不超过 1 pt；插入点遵循所在行实际字体度量，不能将更高回退字形强套固定高度。
2. 同时核对原生截图、插入点／选区与 `firstRect` 的非零有效矩形，保留正确的字符范围与位置映射；空态到首字不跳动，正文或 marked text 出现时占位文字立即隐藏且不叠绘；增量输入、退格和改宽后不得重复插入末尾行片段。
3. 验证中文组词、emoji／组合字形、选择替换、粘贴及撤销重做，避免候选窗跳位、重影或裁切。保留现有 Enter、Shift+Enter、Esc、回焦和拖动规则。
4. 在 560／360 pt、浅／深色、快捷输入／便签及手动高度下确认几何，保持已交付的回缩与滚动行为。遵守 [AGENTS.md](../../AGENTS.md) 的真实窗口授权边界；未覆盖的输入法和焦点手感明确列为人工检查。
5. 在后续最终实现上运行构建及相关既有测试，不新增永久测试，分别报告代码、真实窗口、人工验收和安装状态。完成后合并行为到 Current，才删除本 Work 及索引。

## 非目标

不改字体、外观、快捷键、action 路由或 Notes 配置，不新增富文本、历史或常驻 UI。本项不再依赖已结束的 Notes 授权任务，也不隐含永久安装授权；保留其他任务的所有改动。
