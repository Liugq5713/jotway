# 编辑区光标对齐：改进与交付方案

> Role: **Work**
> Status: 方案已确认；核心修复已在工作区，等待串行集成验收与安装交付。
> 需求编号：`docs/product/editor-refinement.md#cursor-alignment`（沿用既有调度项）

## 问题与范围

用户选择 16 pt 正文和中性表面后，反馈输入后的光标与正文不齐。原实现用 `minimumLineHeight = 26` 实现行距，导致原生光标被拉长、字形偏向行框下方。当前工作区已改用原生字体行框加额外行距。本方案用于核对现有修复并完成交付，不重复实施已完成部分。

## 改进清单

1. **光标随字体，行距单独计算。** 保留常规 16 pt 系统字体，以 `lineSpacing = max(0, 26 - naturalLineHeight)` 实现普通中英文 26 pt 基线间距。自然行高由 AppKit 针对实际字体计算，不硬编码光标高度，不设置 26 pt 最小行框，不单独挪动或重画光标。
2. **统一正文、占位文字与选区的排版。** 保持正文、typing attributes 与 placeholder 的字体和段落参数一致；继续由原生 TextKit 排版。空态到首字不跳动，输入或中文 marked text 出现时立即隐藏 placeholder，不与正文叠绘。
3. **检查连续输入与多行编辑。** 覆盖中文、英文、混排、emoji/组合字符、自动折行、Shift+Enter、尾部空行、选择替换、粘贴和撤销重做。保留中文组词中的原生按键处理，以及原有 Enter 执行、Esc 保留草稿、回焦和拖动行为。
4. **按实际文本几何计算高度。** 保持 90 pt 卡片最小高度、360 pt 卡片上限和 296 pt 编辑区上限。正文高度使用 TextKit 实际排版结果与必要的末行墨迹边界；26 pt 指基线间距，不用“行数 × 26”推算末行底边。普通文字、高字形和滚动到底的末行均不得裁切，动作行始终可见。
5. **在最新集成版本中验收并交付。** 等当前 Notes 授权任务结束后，核对修复已包含在最新代码，完成构建和相关既有测试，再按仓库规则更新同 bundle identifier 的安装版、核对进程。同步刷新受影响的真实产品截图；如果当前安装已经带入修复，验证后回执，不重复安装。

## 验收条件

- 在 560 pt / 360 pt 宽、浅色 / 深色下，正文 16 pt、中性表面和既定留白不变。普通中英文两行的基线间距为 26 pt，光标与所在行字体的排版框中心差不超过 1 pt；该数值判定不强套于更高的回退字形。
- 使用真实 `EditorView` 中的 `NSTextView`，检查空态、首字、行首/行尾及多行位置；测量真实光标几何并目检原生截图，不能以网页示意替代。
- 上述连续输入场景无重影、跳位、末行裁切，达到高度上限后可正常滚动，动作按钮不被挤出。保持已完成的输入卡空白处回焦、保留选区及拖动修复。
- 基于交付用的最新源码运行 `swift build` 和相关既有 `MainPathTests` / `JevPanelTests` 或等效的隔离验证；本需求不要求新增测试。来源任务的旧快照验证不能替代最新集成验证。
- 遵守 [AGENTS.md](../../AGENTS.md) 的 UI 边界：默认不自动驱动用户的 Jotway.app；真实输入法候选窗、切换及焦点手感未验证时，明确列为手工检查。安装时遵守同 bundle identifier 校验与正常重启规则。
- 完成回执必须区分代码、验证和安装状态。完成后核对 [Product overview](../product/overview.md) 的 Current 描述，删除本 Work 及其索引项。

保持既有第 5 项的接收顺序与对 Notes 授权任务的依赖。此文档为该项补充正式版本与验收清单，不创建第 6 项，不重复派发核心修复，不打断当前编码任务。
