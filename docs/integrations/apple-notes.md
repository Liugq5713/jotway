# Apple Notes action

> Role: **Current**

Notes is the only bundled storage fallback. Weekly/monthly reviews use their own folder scope and read authorized originals on demand, independently of the save destination.

Apple Notes is the preferred storage fallback once a destination is configured and no known permission failure prevents execution. When it needs configuration, the panel offers Set Up Notes as an explicit target and as the fallback when no other storage action can execute.

## Routing

Explicit phrases such as “记一下”, “存备忘录”, “save to notes”, and “take a note” can match locally, including when Notes needs setup. A user can select Notes directly from the target menu. Routing does not request a model; setup is never an execution candidate or a prewarmed action.

The `@` picker offers input templates and only edits the draft. Old `@notes` text is literal, including when Notes is explicitly selected. Before supplementation and saving, Jotway preserves the complete original draft, its leading text and whitespace; it does not remove an action marker.

Without a stronger explicit target, bundled keyword or qualified local application match, Notes is the only bundled storage fallback. If it is not ready, Set Up Notes opens configuration. An unavailable explicit target retains its error instead of silently switching to Notes.

## Authorization and configuration

Pressing Enter or Command+Enter in the editor with Set Up Notes selected opens a single configuration window with an Allow Access button and an explanation of the default destination. Clicking Allow Access makes the Apple Events request that can trigger the macOS consent dialog. Opening the setup window or action settings page, typing, rendering the panel, background recognition, and action prewarming do not request Notes permission.

After authorization, Jotway keeps the saved destination when it is still available. Otherwise, it selects the default folder in the default Notes account, then another account's default folder, then the first exposed folder if no account default is available. Successful launcher setup completes automatically. Settings → Apps shows the selected destination and offers Change… to open the optional folder picker; the launcher setup window has no picker. Authorization and destination selection do not create a test note, and no verification step is required.

The draft, selection, and draft identity are retained while recognition is paused. Repeated confirmation focuses the existing configuration window. Completing, cancelling, or closing configuration returns to the same draft; successful configuration selects Notes and waits for another Enter before saving. A stale configuration callback cannot replace a newer draft or take its focus. Setup does not clear the draft, play a submission animation, or record action execution or model-adoption feedback.

Permission refusal and revocation retain the selected destination and direct the user to System Settings → Privacy & Security → Automation → Jotway → Notes. When authorization or the saved destination needs repair, settings and launcher setup offer Open System Settings and Allow Access Again. They do not reset permissions or promise that macOS will show the consent dialog again. A successful authorized read clears the known permission-failure state.

## Execution

The following preparation-first flow applies when daily grouping is disabled. The default grouping flow is described below.

1. On confirmation, freeze the complete original draft and action configuration, reject whitespace-only content, and immediately clear the accepted draft and hide the panel.
2. Run optional AI supplementation in the background. Model output contains only bounded supplement items, never replacement note text, tags or a title.
3. Resolve the initial title independently, assemble the title, a blank line, complete original text and any valid additions, persist complete non-content boundary fingerprints, then create one note through the Apple Notes adapter. Closing or reopening the panel does not cancel an accepted submission. A pending title may later receive a guarded title-only update; ordinary supplements are not refreshed.

After Notes confirms the original save with a note identifier and any required readback, Jotway shows a lightweight “Saved to Notes” completion notice without automatically opening the note or taking keyboard focus. Clicking the notice body opens or activates Notes; it does not save another note or promise to select the created note. Submission acceptance and background supplementation alone do not trigger this notice. It follows the shared [completion feedback](../product/overview.md#completion-feedback) behavior.

The ordinary path adds an independent semantic title and a blank line, then includes the complete original body once in each HTML and plain-text representation. It does not remove action markers or the first original line. It preserves leading and trailing whitespace, blank lines, repeated spaces, tabs, indentation, intentional repeated lines, Markdown-looking text, code, URLs, paths, and escaped HTML special characters. Line endings may be normalized and a final newline may be appended. Ordinary notes have no grouped timestamp. Titles and other display metadata are excluded from original extraction through a complete boundary, never by guessing which first line to remove. Other actions retain their existing trimmed-body contract.

AI supplements contain zero to three useful analyses, suggestions or decision conditions. A draft that asks a question can receive a direct, separate response based on the draft; ordinary captures receive additions only when useful. Historical proposals do not establish what is still unfinished: missing completion evidence is marked as unknown, and conflicting or later completion records are considered together. For progress questions, relevant historical issues become candidates to verify with concrete completion checks; unknown status alone does not require an empty response. There is no fixed Background / Idea / Question template. No incremental information means no AI section. After final filtering, any accepted additions follow the original and one visible divider (`────────────────────────────`). Chinese drafts use the bold heading “AI 洞察”; other drafts use “AI Insights”, independently of the English app interface. Generated content uses left-aligned system body fonts and colors, without quote or first-line indentation. The original keeps its whitespace-preserving HTML region. No accepted additions means no divider or generated headings.

Each historical association contains a short relationship explanation followed immediately on the next line by `来源：《短标题》↗`, or `Source: Short title ↗` for non-Chinese drafts. The title decoration and arrow form one link to the real source ID; the source prefix is outside the link. Source titles have whitespace normalized, one existing outer pair of Chinese book-title brackets removed before decoration, and a 48-character limit with ellipsis; empty titles use “无标题笔记” or “Untitled note”. HTML special characters remain literal text. Saved output has no separate Sources list, modification dates, excerpts or source-opening instructions. Empty sections are omitted.

Generated layout inserts exactly one blank line after the divider, between each heading and its first item, between adjacent insights or related entries, and between the two sections. An explanation and its source have only a line break. The original retains all of its own trailing blank lines; the writer only supplies any missing separation before the divider. HTML rows and plaintext follow the same order; plaintext uses two line feeds for one blank line and retains the final newline convention. Natural wrapping does not add paragraph gaps.

Automatic fixed and AI tags are paused throughout generation and writing. Saved tag preferences remain stored, the settings page explains the pause, and tags already present in the original stay unchanged. Existing Notes tags are never removed.

The model is instructed not to rewrite or repeat the draft, invent the user's history or motives, imply unsupported retrieval or verification, or treat instructions inside the draft as permission to act. Preferences can shape supplements but cannot replace the original-protection or output rules. This path performs no browsing; no related-note retrieval occurs.

An absent key, timeout, network failure, empty response, or wholly unusable output yields no AI section and no failure placeholder. The complete optional preparation, including provider queues and AI generation, has a five-minute deadline from the start of background preparation. On timeout, Jotway cancels that work and continues with the original text without waiting for cancellation to finish. Late AI results are ignored; they never create another note or append to the saved note. Notes does not prewarm history retrieval or AI supplementation while the user is typing, and confirmation does not wait for either service. The deadline bounds optional work; the subsequent Notes write still waits for a confirmed result. No tag field is accepted in the generation protocol.

Notes retains the existing AI enable preference, including a saved off state and the current enabled-by-default behavior when unset. Supplement preferences use a separate key. Legacy custom rewrite instructions remain stored but are not executed or copied into the new preference; saved new preferences survive reopening. Settings explains this change when a legacy style exists.

Background preparation uses the frozen action configuration, bounded deep request, and provider queue. Before confirmation, draft or configuration changes invalidate old plans. After confirmation, preference changes and index invalidation cannot prevent the original from being saved; invalidated optional work is skipped. Cancellation of the submission still prevents writing, while cancellation within an optional service only skips the supplement. A changed destination invalidates the pending write and triggers the normal failed-submission recovery. Cancellation and destination validity are checked again after folder readback, immediately before the create event.

## Recent saved documents

Only confirmed successful Notes outcomes with a valid note identifier populate recent-document references. New notes and daily grouped appends use the same rule: a repeated ID moves to the front with its latest confirmed save time, and only three unique references remain. The single footer entry is available after a confirmed save on the current local day; this condition does not delete older references or restrict browsing to today. Failed or uncertain outcomes, draft edits and other actions do not qualify. Startup never scans or backfills Notes history.

Opening the entry or navigating the lower detail card explicitly reads that document's current plaintext through the public Notes Apple Events interface. It does not use a saved body snapshot or a model. The session cancels and invalidates previous reads when selection changes; loading and failure do not prevent navigation. Closing, hiding or changing mode discards transient content. The `notes.recentSavedDocuments.v1` preference still stores only IDs and confirmed save times. See [Launcher appearance](../../openspec/specs/launcher-appearance/spec.md) for exact navigation and lifetime rules, and [Recent saved documents](../product/overview.md#recent-saved-documents) for the product flow.

## Initial titles and same-day recovery

Every newly created note resolves a title from its first complete original through the fast text capability, independent of grouping and AI supplementation. A valid classifier `new` title is reused; appending preserves the existing title and makes no new title request. The fixed protocol asks for a specific semantic title in the original language, preferably 8–20 characters and at most 48. Validation rejects empty, multiline, oversized, HTML, date-prefixed and greeting-prefixed output. It never truncates the original to make a fallback title. Title requests contain no candidate history or generated supplements.

One title round permits at most three calls within 30 seconds including title/provider queueing and backoff, with each call capped at eight seconds. Backoff is one then three seconds, extended by a valid Retry-After only when it fits the remaining budget. Temporary network errors, 408, 429, 5xx, timeouts and invalid titles may retry. Authentication, balance, 400/422, unsupported-model or oversized-input errors pause until configuration changes. Cancellation, stale configuration and late results cannot be adopted. This retry policy belongs only to initial titles; it does not change other model consumers. Jotway AI activation uses one attempt and pauses automatic title retries after any failure, including uncertain network outcomes, to avoid repeated quota charges.

When a title remains unavailable, Jotway saves the complete original once under “标题待生成” for Chinese text or “Title pending” otherwise. The confirmed note retains its layout, first-entry identity, title state, completed background-round count, next attempt and non-secret fast-configuration version in the management ledger. Existing notes and pre-title snapshots do not acquire title tasks. Missing safety metadata still permits an original-only emergency save with a temporary title, but forbids automatic recovery for that note.

Pending work resumes only for the configured destination and current local day. Its durable schedule is one, five, fifteen, thirty, then thirty minutes; a restart does not reset it. A configuration change wakes paused same-day tasks. One coordinator serializes title request rounds globally and selects the earliest due eligible task, while pending/unknown external writes remain excluded. Cross-day tasks expire without changing yesterday's note. Disabling grouping, supplementation or history does not cancel title recovery; changing destination or fast credentials/binding invalidates prior results. Credential-change revisions persist as non-secret preference counters so the comparison survives restart.

Recovery generates outside the Notes write FIFO, then rejoins it to read and validate the latest note ID, destination, creation day, full body, permissions and attachment state. Only the still-pending title is replaced: all latest originals and generated regions remain byte-for-byte equivalent in the boundary. When the app's title span survives, all remaining HTML is retained exactly; otherwise complete verified plaintext is rendered and old link presentation may be unavailable. Appends and late supplement refreshes retain the current title. Confirmed title replacement has no second save notification and cannot restore an old draft. Unknown results, including cancellation after dispatch, retain the expected pending version and are read-reconciled without repeating the write. Manual edits fail closed.

Settings explains the independent title behavior, missing fast-model configuration and same-day recovery. Content-free title diagnostics distinguish request attempts/elapsed time/error class from confirmed title adoption and durable pending/paused/conflicted/expired states. They contain no note IDs, titles, original/generated text or credentials. Real Notes formatting, model title quality and external-editor races remain separate manual acceptance boundaries.

## Daily project grouping

Settings → Apple Notes provides an independent daily grouping switch, on when unset and preserving an explicit off state, plus Fast Model configuration status and a disclosure that today's candidate originals are sent for classification. It does not require AI supplementation. Turning it off restores the ordinary path above.

Only notes created by this feature today in the configured destination are managed. Existing notes are not taken over by title, and older notes are never modified even if edited today. The frozen fast invocation compares new text with complete ordered originals from verified candidates, preferring to append when the originals support a reasonable, specific and useful shared work or research topic. Short descriptions, parent/child topics, adjacent subtopics, different tools or repositories, and a narrower existing title do not alone require a new note. Browser testing, Agent testing and testing-tool selection can share an automation-testing research topic without an explicitly repeated goal. “Project” means the user's work, not a reference repository's identity. Different concerns or opposing views within one effort stay together; explicitly different work and unrelated content do not merge under generic labels such as “technology.” With multiple relevant candidates, the best-supported candidate wins; only genuine ambiguity, no useful common topic, explicit work boundaries or unrelated multi-topic input causes semantic fallback. Missing credentials, invalid output, a returned-model mismatch, the 128 KiB request cap or a classification deadline still causes independent storage. Existing titles stay unchanged and no historical groups are merged. Nothing is split, silently truncated or moved later.

Each accepted submission has a 300-second grouping decision budget. FIFO queueing, pending reconciliation and initial candidate preparation can use at most 180 seconds, reserving a separate 120-second classification window that starts when candidates are ready and includes the model queue. One cross-day reselection shares the original overall deadline and uses at most its remaining time. Preparation or model timeout settles once and ignores late read/model results. An expired queued submission still waits for its safe FIFO turn before saving independently. These limits do not time out, bypass or retry a dispatched original write; uncertain outcomes retain their pending identity. Original confirmation and the later AI refresh use their existing independent rules; refresh retains its own 300-second limit.

The module-owned FIFO coordinator serializes ordinary and grouped original saves, title adoption and refresh writes. A managed note displays its stable topic title followed by each complete original in submission order, preceded by a separate `- HH:mm` line in the submission time zone. It has no standalone date line or displayed seconds/time-zone suffix. One blank line separates title/time, time/body and adjacent entries, in addition to all whitespace already in the original. Full timestamps, time zones, identities and sequence remain stored; entries in the same minute are distinct. Old-format boundaries remain readable; only otherwise-permitted current-day writes redraw the compact format, never reads or a historical batch migration. Intentional repeated submissions remain separate; recovery of the same submission does not append again. Date and time zone are rechecked before dispatch. A date change reselects current candidates, with at most one reclassification; old-day targets receive no update.

After the original is confirmed, optional assistance processes the full accumulated originals. Its history query prioritizes the latest entry within the existing 4,000-character query bound, excludes the current note and may read older notes within the existing authorized history scope. One shared AI Insights / Related Content tail is replaced, not accumulated. A new original cancels the older refresh and invalidates its revision. The refresh deadline is 300 seconds from scheduling, including preparation and queueing. Invalidated history, destination, day, configuration or body prevents adoption. Generation failure or timeout never restores an already-saved draft or emits another save notice.

When prior generated content remains after an append, a short notice gives its coverage time and says the latest ideas are not included. Successful replacement removes the notice; a valid empty response removes both the old tail and notice. Missing/failed/over-budget generation retains the stale tail; no prior result means no empty placeholder. Turning assistance off cancels its work while leaving grouping enabled; the next managed original write removes old generated content. Changing a switch alone does not rewrite Notes.

The coordinator retains a bounded in-memory cache of confirmed originals, title and generated tail, isolated by destination, local natural day and time zone. Its default text-payload budget is 16 MiB, with least-recently-used eviction; it is not a process-memory guarantee. Evicted or oversized entries are recovered completely for the current submission, so eviction never reduces the candidate set or truncates text. Restart starts cold. Scope changes and disabling grouping clear the cache; cancelling only optional AI work retains valid originals. Confirmed original writes, refresh writes and pending reconciliation update the complete cached revision. The cache adds no persistent body copy and is independent of reviews.

Candidates come from the local same-day management ledger. Cold entries receive one full read. Warm entries check only ID, actual folder, creation/modification dates, lock and sharing state through the public per-property interface; they do not read title, body, HTML or attachments. Arbitrary-ID batch reads are not enabled. Changed state triggers full recovery and boundary validation. Temporary service/permission/read failures end that preparation attempt without permanently marking the note conflicted or classifying an incomplete candidate set. Confirmed edits, moves, deletion or inaccessible note state protect the affected note. Metadata is only a cache hint, including when external edits share its timestamp precision.

Content-free grouping diagnostics correlate queue/preparation/model time, final-validation/readback I/O time, actual Apple Event read-send counts, candidate/cache counts, model placement, final save kind and fallback reason. Reads are counted at the transport send boundary, separately from writes and model calls. Reports contain no Notes IDs, titles, original text, model reasons or credentials. Late results cannot alter a completed report.

Before update, the public Apple Events adapter verifies the note ID, destination, creation day, readable unlocked/unshared state, attachment absence and exact full-body version, then sets the body and reads it back. This adapter guard is the sole final full pre-read; the coordinator does not repeat it. Managed confirmation returns a coherently checked body and metadata for cache installation, and managed ordinary create uses the same complete confirmation contract. Detected edits, moves, deletion, attachments, locks or sharing protect the old note; a new original gets an independent note. A changed destination invalidates the original write instead of silently changing folders. Metadata storage failure before dispatch falls back to an independent original-only save. Unknown create/update outcomes retain a pending identity and expected fingerprint; later complete readback can confirm them, but an unproven outcome never triggers a blind repeat. Restart recovery only resumes valid current-day work.

Management stores hashes and identity metadata, not another body copy. Full-version and per-region verification separates original entries from titles, times, stale notices and generated content during classification and indexing. HTML attribute removal is tolerated only if complete plaintext still matches the ledger. Whitespace changes beyond normalized line endings fail closed. If Notes removes generated HTML markup, retained stale content can be recovered as plaintext and source links may lose clickability until regenerated. Public read-then-write is not an atomic compare-and-swap with external editors; an external edit between the last check and the write remains a race. Real Notes normalization, update/rendering and model quality require separate real-environment evaluation.

## Success and failure

Success requires a confirmed note identifier; managed writes also require the expected complete body and folder readback. Original success and optional refresh failure are separate outcomes. Folder reads preserve the distinction between permission refusal (`-1743`), an empty folder list, a missing destination, and a Notes launch failure. Permission errors are not displayed as an empty folder list.

Missing destination, empty content, permission failure, or an unconfirmed write response returns an error to the panel. The panel restores the original text unless a new draft already exists, in which case it retains the failed submission separately. A permission failure also makes Notes configurable again without erasing its saved destination. Jotway does not automatically retry a write whose outcome may be unknown.

## Boundaries

- Jotway does not keep a second original-text copy for provenance. The origin ledger holds note IDs, format versions and whitespace-normalized original/generated-tail hashes and lengths; no search index stores derived plaintext.
- Configuring Notes is separate from submitting the draft.
- Permission details belong to the Notes module; the launcher hosts a generic setup flow.

## Notes Review and original boundaries

Weekly and monthly reviews are explicit, read-only requests over the last 7 or 30 days of modification times. They require an existing Notes grant and the active text model. Notes Review has its own switch and all-folders/custom-folder scope in Apple Notes settings; an existing history scope is retained without widening it. No background indexing, vector generation, related-note search or embedding configuration remains.

A request reads public Notes metadata in scope, selects at most 60 of the newest modified notes, extracts verified original text and sends at most 4,000 characters per note to the active text model. Locked, unreadable, empty or ambiguous originals are skipped; skipped sources, attachment content, missing selected folders, truncation or a 60-note limit produce a coverage notice. Metadata/permission failures and a wholly failed nonempty read are errors, not cacheable empty results. Review does not request permission implicitly, write Notes, or change the draft. Completed weekly/monthly results have separate six-hour in-memory caches; refresh rereads Notes. Closing, changing scope or losing permission cancels pending results.

`NotesOriginStore` retains the existing `notes-index.sqlite` path solely for original/generated boundary fingerprints. Its migration drops old source, chunk, vector and index-state tables and vacuums the cache, preserving original and daily-origin ledgers. It does not retain note bodies. The sqlite-vec library remains only to open and drop legacy virtual tables; no embedding requests or search queries can execute. Old service preferences and credential files are not read by the application.

Before writes, the ledger stages hashes and lengths of originals and generated tails and attaches the confirmed Notes ID afterward. Pending fingerprints protect uncertain writes. Generated additions are omitted if provenance cannot be staged. Verified boundaries and intact original markers exclude generated material from reviews; edited or inconsistent boundaries are skipped rather than treated as user evidence. Existing saved notes and their source links are not rewritten. Existing `jotway://notes/open` links still open the exact stored source ID through the public Notes interface.

## Model capability ownership

Notes receives `ModelConfiguration` from the app. A stored Jotway code routes titles and classification to hosted Flash and supplements/reviews to hosted Pro. Without a code, all text capabilities share one personal Claude or OpenAI-compatible model. There are no backup models or cross-provider retries. Each accepted save freezes its invocations; candidate/JSON validation, original-first writes and revision guards remain business-owned. Classification retains 120 seconds, separate from the 180-second candidate-preparation budget. Supplements receive the remainder of the existing 300-second deadline including provider queues. Cancellation, invalidation or failure cannot repeat a Notes write. No embedding capability is exposed.

## Web links in original text

A complete, valid HTTP/HTTPS URL on its own line is rendered as an explicit anchor inside the original region. Its full query and fragment, visible text and surrounding whitespace are preserved; other Markdown remains literal. The same renderer serves ordinary create, daily append, supplement refresh and retained generated sections. Web attribution remains original draft text even when AI is disabled or fails. Existing saved history links continue to use the Notes deep-link handler. Chrome Source supplies editable attribution only when explicitly enabled; it neither selects Notes nor attaches hidden metadata.

Service credentials are configured once in AI Services. The Notes grouping section links there. Notes Idea Preferences and the legacy preference notice live in Writing Preferences, alongside automatic thinking prompts and background instructions; the Notes Add Extra Ideas section links to that page. Moving these controls preserves their saved values and feature switches.
