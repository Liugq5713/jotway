# AI provider implementation

> Role: **Reference**

`AppState.models` owns `ModelConfiguration`. `plugin.ai.personalModel.v1` contains one `PersonalModelConfiguration`: service type, base URL, model ID and a credential-store namespace. The key stays in `APIKeyStore`. Legacy `plugin.ai.textBindings.v1` is read only for migration; its fallback entries never execute. Unknown selections and corrupt preferences stay unavailable until repaired. Existing source injection is retained for isolated callers.

The configuration boundary checks `HostedAIState.hasCode` before personal preferences. An unreadable hosted credential also blocks personal routing. The hosted configuration captures the code from the same state object used for activation and quota, rather than independently selecting another credential store. Activation preserves personal metadata. Removing a code restores personal routing for new snapshots; failed hosted requests never do so.

`PersonalModelConfiguration.normalized()` validates metadata before constructing an endpoint. Only HTTPS base URLs without user/password, query or fragment are accepted. The native Claude adapter appends `messages`; the compatible adapter appends `chat/completions`. Changing the address or service requires the user to re-enter the credential. A same-service/address model change can reuse it. The UI never reads saved key text into a field.

`ModelTextRequest` carries assembled instructions, content, output format, ordinary and thinking-model token budgets, byte limits and timeout. `ModelTextInvocation` freezes one provider configuration including credentials. `ModelTextExecution.bounded` preserves the 120/300-second fast/deep deadlines including the provider actor's queue; shorter caller deadlines win. Deep requests and tests stream even without a preview subscriber. There is one attempt, no provider fallback or nonstreaming replay. Independent snapshots keep separate serial provider actors. `ModelDeadline` returns without joining uncooperative cancelled work.

`ModelStreamEvent` retains invocation/attempt identity, provisional content and synchronous validity checks. Only the current request may publish, and recipients must recheck scope/configuration identity before adopting a queued update. A final complete string remains the success boundary. No partial response authorizes a cache entry or Notes write. Runtime logs contain bounded metadata; Notes does not install the optional content diagnostic receiver.

`OpenAICompatible` sends Bearer authorization and reads Chat Completions JSON or SSE. Generic services receive a JSON instruction rather than an assumed `response_format` capability. Known official DeepSeek/Kimi hosts keep their specific JSON/thinking behavior; these fields are never sent to arbitrary endpoints. SSE requires a valid returned model identity, a consistent identity across chunks, `finish_reason: stop`, and `[DONE]`. Truncated, malformed or tool responses fail. Hosted models require exact matching; personal aliases may resolve to a different concrete returned ID. Reasoning content is not adopted.

`Claude` sends `x-api-key`, `anthropic-version: 2023-06-01`, a top-level system prompt, user messages and the caller’s declared thinking/output total budget when available, otherwise the ordinary output budget. JSON requests add an explicit JSON instruction, then rely on business validation. The native response requires an assistant message, model identity, text content and `end_turn`. The stream validates message start, sequential content blocks, their endings, `end_turn` and `message_stop`. Thinking/signature content is ignored, error events fail, and unknown metadata events do not bypass completion checks. Both response modes are bounded to 2 MB while reading; answer bytes also obey the caller limit. Native Claude protocol references: [Messages](https://platform.claude.com/docs/en/api/messages/create), [streaming](https://platform.claude.com/docs/en/build-with-claude/streaming).

Both transports refuse redirects, use ephemeral sessions, propagate cancellation and report fixed error categories rather than raw server bodies. The settings connection test uses the active central route and a 30-second deadline with fixed sample text. A stored code therefore tests Jotway; personal edits stay inactive until code removal. Tests and previews are invalidated by configuration or credential changes.

Only fast/deep text capabilities are callable. Embedding configuration and transport have been removed; Jev remains historical metadata only.
