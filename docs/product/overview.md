# Product overview

> Role: **Current**

Jotway is a native macOS launcher that brings Apple Notes and local application launching closer to short, in-the-moment input. The user opens a small panel, types a sentence, checks or changes the proposed destination, and presses Enter. Jotway hands the content to the chosen action and leaves no local inbox behind.

From another app, the existing recording shortcut can quote selected plain text before the hidden quick-input panel takes focus. Supporting controls need Accessibility permission; unavailable selection falls back to the same recent-copy rule. The quotation remains editable and undoable, and reopening the same draft does not repeat a successfully adopted selection. Menus, Dock, guides, sticky notes and visible panels retain their existing opening behavior. See [Selected text](../../openspec/specs/selected-text-capture/spec.md) and [browser-source fallback](../../openspec/specs/browser-source-capture/spec.md).

## Main flow

1. Open the quick record panel from the global shortcut, menu bar, Dock, or application launch.
2. Enter plain text. Markdown-looking syntax, `/`, and `、` remain literal text; pasted rich text loses its styling, while image-only and file input is ignored.
3. In quick input mode, Jotway combines explicit selection, local action keywords, local application matching, and the Notes default to choose a destination. A direct application name or `打开 应用名` can resolve to a local application launch without opening a separate command menu.
4. Press Enter or Command+Enter in the editor to execute. If the target is Set Up Notes, Enter opens configuration and retains the draft; after setup, press Enter again to save. Shift+Enter inserts a newline.
5. When a text submission is accepted, the panel clears and closes and the next draft uses automatic routing. Failure restores the submitted text and its routing mode unless the new draft has already been edited or its routing changed; otherwise the failed submission is retained separately.

## Quick record panel appearance

The panel starts in quick input mode. Its small mode control switches the same window and native editor to a temporary sticky note. Both modes share one draft, selection, insertion point, undo history and explicit target choice. Switching does not submit text or create another body version. Sticky mode shows the editor, return control and thinking prompt entry, plus a recent-document entry when eligible, with a shared read-only area below the input: Enter and Shift+Enter insert newlines, Command+Enter does nothing, ordinary Tab edits text, and `@` stays literal without completion. Return to quick input to execute an action; routing and ordinary preparation are rebuilt from the current text and require a fresh confirmation. Recognition, candidate menus, Clipboard results and recent Codex tasks remain hidden and inactive in sticky mode. Already accepted background actions continue; a late failure is kept separately until the user returns to quick input and restores it.

Both shapes place the mode control at the left end of a 22 pt bottom footer, below the editor. The mode control and the single recent-document entry have 22 × 22 pt hit areas outside the editor; quick input keeps the target capsule on the right. The monochrome `doc.text` entry is available only after a confirmed Notes save today and opens the latest document; navigation between retained references lives inside the lower detail card. Eligibility and navigation follow [Launcher appearance](../../openspec/specs/launcher-appearance/spec.md). The redrawn mode glyph is about 12 pt: a rounded folded note in quick input, and a rounded input window with a caret and text line in sticky mode. It has no resting tile or outline. Hover adds a soft blue-gray tile with a 6 pt corner radius, a thin outline, a stronger glyph color and a pointing-hand cursor. A press briefly strengthens the background for 100 ms without moving or scaling the control; keyboard focus adds an accent outline.

Hovering anywhere inside the input card reveals the mode control and an eligible document entry quietly; hovering a particular control emphasizes it. A control's own hover or keyboard focus keeps it visible, while document selection alone does not. Leaving fades unfocused controls out over 120 ms; re-entering cancels the fade and Reduce Motion hides immediately. Controls hidden only by hover retain their native buttons, tooltips, keyboard entry and occupied width. The footer reserves the mode slot and, when eligible, one document-entry slot; without eligibility, the document entry and its spacing are removed. Preparation failure text starts after the available group without overlap or hover-driven movement. The controls retain the same bottom-left anchor for empty drafts and `@` input and stay outside the scrolling text. Quick input retains its card heights and spacing; sticky mode reserves the footer within its existing window size, reducing only the editor viewport. No toolbar, text indentation or wrapping exclusion is added. Shift+Tab reaches the mode control from the editor; Tab after the target selector also reaches it. Return or Space switches modes without submitting. Localized tooltips and accessibility names explain the direction or a temporary block. Composition, getting-started reading, action setup, submission acceptance or application launch prevent switching until that work finishes.

The first sticky note is 300 × 200 pt with a 240 × 160 pt minimum, anchored at the previous window's top-left and constrained to the available screen. It remains floating above ordinary application windows when focus moves elsewhere and does not reclaim keyboard focus. Long text scrolls inside the editor instead of growing the window. Each mode remembers its position, size and quick input height policy separately for the current process. Switching modes stays on the display containing the current window: a saved position is restored only when it belongs to that display; otherwise only the saved size is restored, anchored at the current window's top-left and constrained to that display. Returning to quick input also restores its manual or automatic height policy; reopening quick input still resets manual height as before. Sticky dragging never writes quick input's saved per-screen position. Screen changes constrain either mode to a reachable display without adding new fullscreen behavior.

Esc or the global hide shortcut preserves the sticky draft, mode and geometry. When a recent-document detail is open, Esc closes that detail first; hiding the panel or switching modes also closes it. Reopening does not restore detail or import the clipboard or a browser source. Quit, crash or restart clears the draft, mode and sticky geometry and starts with blank quick input. Existing quick input position preferences and local operation sampling retain their normal boundaries; operation records do not restore sticky notes.

The existing Follow System, Light and Dark setting determines the effective appearance. Light cards keep their opaque warm-white surface. Dark cards use a graphite tint at 0.95 opacity over native material; only the background participates in the blend, while text and controls remain fully opaque. Each input or lower card owns its material and rounded clip, so the gap stays transparent. Reduce Transparency or Increase Contrast replaces the material with an opaque surface; Increase Contrast also strengthens the outline and uses semantic text colors. These changes update the background without recreating the native editor.

The exact appearance contract is in [Launcher appearance](../../openspec/specs/launcher-appearance/spec.md); shared color values live in [EditorPalette](../../Sources/Features/Editor/EditorPalette.swift). The tint opacity is a composition setting, not a promise that screen pixels contain exactly five percent of the original background. Real material appearance remains subject to macOS composition.

The right-aligned target capsule uses 12 pt medium text, 7 pt horizontal padding, an 11 pt radius and a 22 pt height. A 12 pt monochrome target icon precedes the title; a 1 × 10 pt decorative divider separates it from the Return hint. Its resting surface is filled; an open menu uses the distinct active surface from the shared palette. Keyboard focus adds a visible outline, strengthened under Increase Contrast. Pointer hover adds no feedback. The capsule, divider and Return hint share one click area for current-target confirmation; menu state and input protection follow [Launcher appearance](../../openspec/specs/launcher-appearance/spec.md). The capsule remains keyboard-focusable for opening the target menu. Icons come from the same route as the title, with app or a generic symbol as fallback, and add no VoiceOver node. The explicit-selection marker keeps its blue accent. The Return hint uses a neutral symbol in a 16 pt slot without a keycap background; candidate-menu keyboard hints retain their 16 pt square keycaps. Action titles remain one line with truncation, full accessibility labels, and their existing tooltips. The fixed 22 pt quick-input action row shows the mode control and the single recent-document entry, when eligible, on the left, ordinary preparation failure information after the available group, and the target capsule on the right. Failures use a single line, with the full safe reason in hover and accessibility details. Ordinary recognition, operation, and shortcut-trial status text does not appear here. Candidate cards share the neutral surface without changing their layout or interaction.

For a nonempty draft, the target label fits its title up to 120 pt, constrained by the row's available width. The explicit-selection marker, target icon, divider, Return hint, gaps, and horizontal padding reserve another 68 pt. The button's right edge and Return hint stay anchored while its left edge follows the title width; marker visibility does not change its width. Names still change immediately with the current route, and full names remain available through hover and VoiceOver.

Preparation failures and empty content share the fixed 22 pt action row. Editing, composition and target/configuration changes remove obsolete failure and accessibility details. Empty drafts, getting-started reading and hidden/reopened panels retain no stale preparation content. Actual text wrapping, width changes and user resizing still affect geometry.

Application search can find System Settings with `settings`, `sett`, `ss`, `sysset`, or a small typo such as `settting`. It uses discovered names and aliases, including localized names and Chinese pinyin/initials. Exact names and stronger matches win before usage; equally good matches use open count, then recency, then normalized application name and stable identity to choose one result. For example, `voice` recommends Voice Memos ahead of VoiceOver Utility when neither has usage history. Ordinary sentences are not treated as fuzzy application searches. Typo recovery is limited to one edit in 4–32 English letters with the same first letter; generated pinyin and initials do not receive typo recovery.

Automatic routing recommends at most one application on the target button. The manual target menu and keyboard cycle offer only Apple Notes and Codex, according to their existing availability and setup rules; they do not list applications or Clipboard. Let Jotway Choose releases an explicit action and restores automatic matching for the current draft. Enter can still launch the automatically matched application after confirmation checks. A successful pure application launch clears only its own unchanged input; launch failure, edits made while launching, and text following an explicit launch command remain in the draft.

Confirmation waits for current ordinary preparation when necessary, without a time preview or drawing receipt. Editing, changing the target or configuration, composition, and hiding the panel cancel unaccepted confirmation. A new input requires a fresh confirmation.

For ordinary input, the action name appears in the single target capsule, with a Return symbol hint for a nonempty draft and no separate dropdown arrow or execution button. Tab focuses the capsule; Return or Space opens its target menu, even for a single candidate. Clicking the capsule confirms the current target through the editor’s normal confirmation flow; when its menu is open, a click only closes the menu and returns to the original editor selection. Composition and an open review block pointer confirmation. Keyboard target selection remains separate; see [Launcher appearance](../../openspec/specs/launcher-appearance/spec.md). Empty or whitespace-only drafts hide the entire capsule, including Choose an App, while retaining the action row's height. The capsule appears when the draft has content and disappears when it is cleared. Selecting a target pins it to the draft through edits and panel reopening; selecting the same Notes or Codex target currently chosen by automatic routing also establishes explicit mode. The menu's Let Jotway Choose action releases that choice immediately. Only accepted submission, a completed edit that clears the draft, or Let Jotway Choose ends the choice. For a nonempty draft, an unavailable explicit target remains visible until the user changes mode or target.

Typing `@` at the start of a single-line quick-input draft opens a template picker below the input card. The fixed “记录想法” and “梳理问题” templates come first, followed by custom definitions from Settings → Templates. Query text filters names ignoring case, including spaces. Up/Down and Tab/Shift+Tab move the highlight; Enter, Command+Enter or a click replaces the entire query with expanded editable text. This is one undoable edit, retains any explicit target and never sends or starts setup. Esc dismisses the picker until text changes; Shift+Enter inserts a newline. Composition, sticky mode, active filling, multiline drafts, email addresses and unmatched queries do not open the picker. Definition updates retain a valid highlighted ID and reject stale choices.

The picker has one Input Templates heading with a monochrome icon. Each fixed or custom row shows its name above a quieter body preview, with a reserved Return hint on the highlighted row. Both lines truncate at the end; help and accessibility expose the full name and preview. Previews use the local placeholder expansion, keep defaults and escaped literals, trim line whitespace and trailing colons, and join nonempty lines with ` · `. Invalid or empty previews show No body preview without changing selection validation. Only the candidate area scrolls, limited by the space below the input card and at most six 52 pt rows; the heading and navigation/Insert text/Esc hints remain outside it. Highlight navigation, filtering, definition updates and height changes keep the current valid candidate visible. Previewing never changes text or target, invokes a model or reads external data.

Template fields use `${n}` or `${n:default}` and are visited numerically; `${0}` marks the final position. Tab advances, Shift+Tab goes back, and the first backward move stays on the first field. Esc ends filling without discarding text; a later Esc follows the normal behavior. IME has priority. Enter confirms through the existing target flow and Shift+Enter inserts a newline. Undo restores the full query and selection; Redo restores only text. Crossing fields, moving outside the current field, switching mode, hiding, replacing a draft or accepted submission ends filling. Templates do not select a destination. Old `@notes`, `@personal`, `@codex` and `@clipboard` names remain literal text and never strip a prefix, hide the target capsule or lock target selection.

Only an accepted leading routing marker is removed before saving, generating assistance, or running a Codex task. Notes preserves the remaining body, including indentation and blank lines, after removing the marker and its separator. Other actions retain their trimmed-body behavior. An empty body cannot execute.

Tab focuses the target capsule when the draft has content; Return or Space opens its menu. Enter inside the menu selects Apple Notes or Codex, or returns to automatic routing, and restores editor focus without submitting; Escape closes only the menu. Option+Up/Down cycles only the applicable Notes and Codex candidates and never cycles through Let Jotway Choose. Enter in the editor retains the existing submission or application-launch confirmation behavior. Text composition takes precedence over these keys.

The candidate menu and window height update without layout animation, so opening or closing the menu does not animate the editor's position.

The area outside each card's rounded border and the gap between cards stay transparent. The existing system window shadow remains; no extra outer glow is added. A static single border accompanies the input card's focus glow. In dark appearance, its gray-blue colors, steady intensity and entrance peak are restrained. Losing focus or hiding stops and removes it. Reduce Motion keeps a static inner edge; changing theme or accessibility settings preserves animation progress and does not replay the entrance. Lower cards have no glow. Window entrance/exit and submission animation types and timing retain their existing behavior.

Submission animation snapshots contain only the app's own content. An opaque surface from the effective theme fills each rounded card before the cached image is drawn, preserving transparent corners and the gap even when native material is absent from the cache. No desktop or other window is captured. The appearance reference images are concept illustrations, not running-app screenshots.

The default quick input panel width is 560 pt and can narrow to 360 pt. The input card has a 14 pt corner radius and starts at 122 pt: 20 pt top padding, a 52 pt minimum editor, 12 pt gap, a 22 pt action row, and 16 pt bottom padding. The action row keeps its space when the draft is empty. Actual left/right text padding is 20 pt, including native text-container insets and line-fragment padding. Initial window sizing uses the same dimensions. Empty and one-line drafts reserve two ordinary lines without inserting newlines or centering text; the first line and placeholder keep their original top-left origin. The first two lines keep the card stable until actual native layout exceeds 52 pt. The card grows automatically downward from its top edge to 360 pt; the editor scrolls internally after reaching 290 pt, keeping the action row visible. Adding a line while the card can still grow keeps the existing text in place, without briefly scrolling it up and back down. Deletion and replacement shrink the card from the same top edge using the latest native layout, including trailing empty lines. The scrollable document follows the current text height in both directions and stays at least as tall as its viewport, so deleting long content does not leave an old scrollable blank area.

Dragging a window edge resizes the usable editor area along with the input card. A manually chosen height takes precedence over automatic growth until the panel is opened again, and may exceed the automatic height limit. The action row, including any preparation feedback, keeps its fixed space; longer text scrolls inside the remaining editor area. The candidate menu adds height below the input card. The editor and window share the same screen-constrained minimum: lower content shrinks first, then the two-line preference can drop toward the existing one-line budget and below it only on extremely small screens. Template headings and hints keep their existing single candidate scroller; a target menu that cannot fit scrolls in its lower region. When the window reaches its size or screen limit, the manual input height shrinks to keep those controls visible. The preferred 122 pt minimum does not override the actual available screen; sticky mode retains its separate one-line editor minimum and existing window sizes.

Body and placeholder use the regular 16 pt system font. Ordinary Chinese and English baselines are 26 pt apart: extra line spacing keeps ordinary text on native font metrics instead of imposing a 26 pt minimum line box. Consecutive or trailing empty lines can still include that spacing in their native caret rectangle; this remains a separate [caret geometry follow-up](../development/editor-cursor-alignment.md). Taller glyphs may expand their line rather than being clipped. Both use the same native TextKit layout geometry as the cursor and selection. The placeholder disappears immediately when text or marked text appears, canceling any earlier fade. Deleting all text allows a short fade-in; Reduce Motion shows it immediately. Text uses the full editor width without a persistent Escape badge. Escape still closes the panel while retaining an ordinary draft.

Clicking unused space inside the input card returns keyboard focus to the editor while preserving its text and selection. Dragging that background moves the panel; text selection and action buttons keep their own mouse behavior.

## Recent saved documents

A single document icon beside the bottom-left mode control is available in both writing modes when a valid Notes save has been confirmed on the current local calendar day. Without a save today, the icon and its spacing disappear; older references remain stored. The entry keeps the existing card-hover and keyboard-focus behavior. Opening it starts with the latest saved document, and activating it again closes the detail.

The lower detail card reads the current Notes plaintext by document ID and provides a position indicator and navigation across up to three retained references, including earlier days. Reading, errors and retries remain separate from the draft. Navigation keeps the lower region open, and obsolete responses cannot replace a newer selection. Only IDs and confirmation times persist; startup does not scan Notes. See [Launcher appearance](../../openspec/specs/launcher-appearance/spec.md) for date eligibility, navigation, focus and geometry, and [Apple Notes](../integrations/apple-notes.md#recent-saved-documents) for the integration boundary.

## Thinking while writing

A lightbulb in the footer opens one temporary AI thinking prompt below the editor in either mode. It offers a question, a missing piece of evidence or a comparison criterion; the user continues in the original editor. The prompt shares the lower area with document detail and action content, and never becomes draft or saved text. Manual results remain tied to their generation snapshot.

Writing Help offers an independent, default-off Automatic follow-up prompts preference. When enabled, settled edits can update the prompt without taking focus; closing it suppresses automatic reopening until the text changes. Menus, document viewing and protected input take precedence. Only the current draft goes to the fast model chain. See [Thinking prompts](../../openspec/specs/draft-thinking-prompts/spec.md) for request, privacy and lifetime boundaries.

## Bundled actions

- Apple Notes: preserves the complete original text and can append separate AI thinking assistance; the factory default action.
- Clipboard: searches local clipboard history and restores selected content without a model call.
- Codex: runs explicitly selected tasks in the background using a user-installed helper, with a separate folder for each task. Confirmed completion does not open Codex or a result file.

Apple Notes is the only bundled default. If it cannot execute, Set Up Notes is the fallback. Codex and Clipboard never become implicit fallbacks. An unavailable explicit selection blocks confirmation and retains the draft and target until the user changes the selection.

If the target shown at confirmation becomes unavailable during its live recheck, Jotway blocks that confirmation and retains the draft. It never executes a newly resolved fallback using the same confirmation.

Notes setup preserves the draft and selection, pauses recognition, and uses a single configuration window. It is not a submission: completing or cancelling setup returns to the original draft without execution feedback or automatic saving. Successful setup selects Notes; the user confirms again to save. The explicitly requested connection test creates a disclosed test note, never the draft. Permission refusal retains the saved location and offers Automation settings guidance and another folder read.

## Completion feedback

Completion notifications default to off for all actions. Settings → General → Completion Notifications enables lightweight notices when confirmed execution results arrive. Notes reports “Saved to…” only after the destination confirms creation with an identifier. Codex reports task completion only after its CLI completion checks pass. Accepting a submission, configuring an action, or a failed or uncertain execution does not show a success notice.

The notice appears at the top-right of the screen containing the pointer, inset 16 pt from the top and right edges of its visible area, without taking keyboard focus, activating Jotway, playing a sound, or requesting notification-center permission. It closes after four seconds. Hovering pauses dismissal, leaving starts another four seconds, and the close button dismisses it immediately. A new result replaces the existing notice and restarts its timer. Success messages are not repeated when the quick record panel next opens. Failure recovery remains in the quick record panel.

Clicking the notice body dismisses it and opens or activates the corresponding application: Notes. The Notes entry does not promise navigation to a specific saved item. Codex opens its task conversation, with the saved result or task folder as fallback. This happens only on an explicit click; automatic dismissal and the close button never open an app. It does not resubmit text, create a new conversation, send a prompt, retry execution, or alter the draft or recorded result. If the application is missing or macOS rejects the open request, a separate lightweight notice explains that the action finished but the app could not open. A late opening error cannot replace a newer completion notice.

Selecting Codex in the target menu shows the five most recent tasks started from Jotway, including with an empty draft. Each two-line row emphasizes the conversation name, with time and status below it; the task excerpt is a fallback. Names refresh through metadata-only reads when the list opens. A template or target menu temporarily covers this area. Click a task to open its conversation or saved result without submitting. Successful opening clears the draft and explicit target; complete opening failure preserves both. Records survive restart; unfinished tasks show Check result. See [Codex](../integrations/codex.md).

## Clipboard history

Clipboard remains a registered local action with collection, settings and stored history. It has no entry in the manual target menu or keyboard cycle, and no replacement history entry is provided. When Clipboard is the current target, its history list uses the entire editor text as its query, including any old `@` prefix. A matching template picker temporarily covers the results and selecting a template only edits the query; it never copies. Search matches every whitespace-separated word, ignoring case, against original text or cached OCR. Empty queries show recent items. This route uses no model, AI or network and cannot become the default action.

The list shares the lower card with other action content. Arrow keys or a row click select an item; Enter or Command+Enter copies its complete text or original PNG/TIFF representation. Only successful copy clears the query and closes the panel. Jotway returns focus without sending a paste command. Image OCR never replaces the copied image. Composition takes priority; background results preserve the selected item identity or clear it if unavailable.

Collection defaults on without a saved preference; existing on/off choices and a subsequent manual off choice persist across restarts. It is independent of action visibility and does not backfill copies made before startup. Application settings manage future collection and clear history separately from operation records; the list retains collection status and errors without a Settings link. Disabling collection retains searchable history and cancels OCR. See [Clipboard](../integrations/clipboard.md) for privacy and storage limits.

## Product boundaries

- The editable draft disappears when the process exits. When local operation capture is enabled, stable unsubmitted text is also persisted for manual review; it is never restored as a draft.
- Jotway does not provide an inbox, general content history, cards, or Summary. Recent-document navigation retains only three Notes references for on-demand reading. The explicit Codex target exposes five recent task entries and their execution status. Clipboard is a separate local history of external copies, enabled by default only without a saved collection preference; it does not save editor drafts.
- The editor accepts only multi-line plain text. It does not render or structurally edit Markdown, and it does not accept images, files, or rich-text attachments.
- Local operation records include full input versions, routing, choices, and execution observations. Capture, retention (default 90 days), manual JSONL/CSV export, and deletion are controlled in App Suggestions settings. Records do not automatically change rules.
- Intent recognition proposes a destination; it never performs an action without the user’s explicit confirmation.
- Action failure restores the input rather than silently dropping it.

## Design principles

- One sentence in, one explicit outcome out.
- A usable execution or configuration path exists even when recognition is unavailable.
- Local and explicit signals outrank a model guess.
- Each action owns one descriptor, availability, preparation, and execution.
- Optional AI processing must degrade to a usable non-AI path.

## Chrome copy sources

Chrome Source is optional and off by default in General → Quick Entry. For a newly observed Chrome copy, it can append the current page title and complete HTTP/HTTPS link beside the recent quote, leaving an empty line for thoughts. The existing one-second, once-per-copy window is measured when invoked; a source adds at most 150 ms of asynchronous preparation. Missing access, detected changes and slow reads retain text alone. This is a nearby current-page association, not proof of the exact copy origin. Sources are editable draft text and follow the same routing, AI, history and Local Records settings. Removing a source removes it from submission and failure recovery never rereads the browser.
