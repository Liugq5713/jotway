# Website brief

> Role: **Work**
> Status: candidate public site; it does not describe a published website.

## Goal

Explain Jotway in one screen, show the launcher interaction, and provide a download whose claims match the linked build.

## Core message

**打一句话，Jotway 送到该去的地方。**

The page should demonstrate: open the panel, enter a sentence, check the proposed action, and press Enter. It should not present an inbox, card stack, Summary, long-term memory, or processing workflow.

## Content

- Native macOS launcher for transient input.
- Apple Notes, Reminders, Calendar, and Chrome destinations.
- Explicit confirmation before execution.
- Draft restoration on failure.
- Optional Jev/AI network processing with clear provider and cost disclosure.
- Local intent-feedback storage, including full draft text, its retention limits, and available deletion controls.
- macOS version, CPU architecture, signing/notarization state, version, build, file size, and checksum taken from the actual release artifact.

## Pages

1. Home: product explanation, short demo, action list, privacy summary, and download CTA.
2. Download: current version facts, install/open instructions, checksum, and release notes.
3. Privacy: what remains local, what is sent to each optional provider, retention, and how to remove keys/logs.

## Acceptance

- Every capability claim is verified against the downloadable build.
- The demo uses the current launcher UI and contains no private content.
- Download metadata is generated from release output rather than typed twice.
- Ad-hoc signing and the absence of notarization are stated plainly until the release process changes.
